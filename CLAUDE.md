# FinPulse

Трекер особистого бюджету за зарплатним циклом (8-ме → 7-ме число). Сайт: https://ikunstler-maker.github.io/finpulse/

`docs/SPEC.md` — єдине джерело правди, з поправками з `docs/decisions.md` (рішення власниці).
Якщо запит суперечить їм — спершу спитай. Загальний підхід до роботи — `docs/playbook.md`.

## Як працюємо
- Етап за етапом (SPEC → «Етапи»): план → OK власниці → код → перевірка «Готово, коли» → commit/PR.
- Лише поточний етап. Те, що позначено «Пізніше», не будуємо, але архітектурно не блокуємо.
- Стек: Vite + звичайний JavaScript (ES-модулі) і власний CSS з токенами кольорів (Tailwind і Chart.js
  прибрано під час редизайну), Web Crypto API, Google Identity Services + Google Drive API, GitHub Pages.
  Підказка курсу — НБУ і WhiteBIT (лише за натисканням кнопки).
  Нову бібліотеку чи сервіс — лише з OK.
- Власниця не професійна розробниця: пояснюй рішення коротко, простою мовою, українською.
  Звертайся на «ви». Технічні терміни — з поясненням у дужках.
- Інтерфейс українською; усі тексти інтерфейсу — в одному файлі-словнику `src/i18n/uk.js`
  (з етапу 3). Код, назви й коміти — англійською.
- Ризиковані, дорогі чи незворотні вимоги — піднімай до початку роботи.
- Кожне рішення власниці записуй рядком у `docs/decisions.md` (дата | тема | рішення).
- Коли від власниці потрібна дія — покрокова інструкція: сайт → розділ → кнопка → що вставити.
  Секрети вона вставляє сама у панелі сервісів; ніколи не проси надіслати секрет у чат.
- Звіт після кожної роботи: що зроблено, що перевірено (з цифрами), що потрібно від власниці.

## Злиття PR (правило власниці)
- Дозвіл на автоматичне злиття дається разом з OK на план. Без нього не зливай.
- Зливай лише свої PR і лише із зеленими перевірками; чернетки й прототипи — ніколи.
  Після злиття скажи, що саме пішло на сайт.
- «Небезпечне» злиття — завжди окреме попередження і окреме «так» або «зроблю сама»:
  зміна формату збережених даних або ключа `localStorage` (`finpulse_app_state_v3`),
  перенесення даних (localStorage → шифроване сховище), шифрування й вхід через Google,
  нові секрети або налаштування Google Cloud, усе, що складно відкотити.

## Дані та шифрування (Zero Knowledge)
- Фінансові дані користувача ніколи не залишають браузер незашифрованими.
  Шифрування й розшифрування — лише в браузері (Web Crypto, AES-GCM).
- Ключ даних загорнутий двічі: ключем із пароля FinPulse (PBKDF2/Argon2 — параметри у SPEC)
  і ключем відновлення. Google-акаунт — лише вхід і місце зберігання, не ключ.
- Пароль, ключ відновлення і розшифровані дані не потрапляють у логи, URL, аналітику,
  повідомлення про помилки, Google Drive чи будь-який сервер.
- Сховище в хмарі — прихована папка застосунку на Google Диску (`appDataFolder`),
  мінімальний доступ (scope `drive.appdata`). Інших файлів Диска не читаємо.
- Локально — зашифрована копія для роботи офлайн; синхронізація, коли є мережа.
- Будь-яка зміна формату даних — з номером версії, міграцією і перевіркою, що старі дані
  (і старі JSON-бекапи) відкриваються.
- Значки й тексти про безпеку мають відповідати тому, що реально робить код.

## Секрети
- У браузер потрапляє лише публічний Google OAuth Client ID (він не секретний).
  Client Secret у цьому застосунку не потрібен і не використовується.
- Власних серверів немає. Якщо колись з'являться — секрети лише в GitHub Secrets / змінних
  середовища хостингу, ніколи в коді.

## Команди
- `npm ci` — встановити залежності; `npm run dev` — локальний сервер; `npm run build` — збірка в `dist/`.
- `npm run lint` — ESLint; `npm test` — unit-тести (Vitest, `tests/unit/`);
  `npm run test:e2e` — перевірка в браузері (Playwright, `tests/e2e/`, комп'ютер + телефон, дата зафіксована 29.10.2026).
- Усі формули — у `src/calc.js` (чисті функції). Нову формулу — туди й одразу з тестом.
- Публікація: GitHub Actions (`.github/workflows/deploy.yml`) збирає й викладає `dist/` на GitHub Pages
  після кожного злиття в `main`.
- Інтерфейс: `src/ui/*`. Жодних `onclick` у розмітці — кнопки мають `data-action`,
  обробники в `src/ui/app.js` (діє Content-Security-Policy). Тексти — лише через `t()` зі `src/i18n/uk.js`
  (тест перевіряє, що ключі існують і українських текстів поза словником немає).
- Формат даних — версія 5 (картки `cards` і `cardId`; `src/data/migrate.js`); імпорт CSV/JSON — `src/data/import.js`; нове поле — з перевіркою в `src/data/sanitize.js` і тестом.
- Шифрування і синхронізація: `src/sync/` (engine — логіка й конфлікти, controller — режими local/locked/vault,
  local-vault — зашифрована копія і «запам'ятати пристрій»). У режимі vault відкриті дані не пишуться в localStorage.

## Перевірки
- CI (GitHub Actions) на кожен PR: збірка, лінтер, unit-тести розрахунків і шифрування (Vitest),
  перевірка в браузері (Playwright), включно з розміром телефона. Помилки — як анотації.
- Обов'язкові тести безпеки: неправильний пароль не розшифровує; на Диск іде лише шифротекст;
  ключ відновлення відкриває дані.
- Перед здачею роботи: збірка, лінтер, тести; результат — чесно, з цифрами.
